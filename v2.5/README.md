# Discord 实时翻译助手 v2.5

看 Discord 外文社区时的翻译工具。两种用法：**鼠标悬停**消息弹出半透明气泡显示译文；**自动聊天翻译**开着时，聊天区来了新消息会自动出译文气泡（最多同时保留 6 条，跟着聊天一起滚动）。

- 直接读 Discord 页面的真实文字（不是 OCR / 截图识别），准确率 100%，无识别延迟
- **普通消息、机器人卡片（Embed / Components V2）、抽奖与投票卡片都能翻译**
- 卡片里会精确翻译鼠标所指的那一段，悬停在卡片留白处则翻译整张卡片
- **自动聊天翻译（v2.5 新增）**：新消息自动出译文，气泡贴在消息正上方、跟着滚动走；只翻**屏幕里看得见**的，最多同时保留 6 条，每条 15 秒后淡出
- **目标语言可切换（13 种）**：中文 / English / 日本語 / 한국어 / Русский / Español / Français / Deutsch / Português / Italiano / Tiếng Việt / ไทย / العربية
- **界面语言可切换**：简体中文 / English（给外国同事用）
- **已经是目标语言的内容不会翻译**，也不发请求 —— 又准又快又省钱
- **气泡颜色和透明度可调**（12 个预设色 + 自定义取色器）
- 翻译结果本地缓存，同一句不重复请求、不重复扣费
- 不修改 Discord 任何文件，也不读取账号密码

## 本版（v2.5）改了什么

| 改动 | 说明 |
|---|---|
| **自动聊天翻译（新功能）** | 聊天区来新消息就自动出译文气泡，最多同时保留 6 条，第 7 条进来时最旧的那条**渐变淡出**。气泡贴在消息正上方、跟着聊天记录一起滚，不会错位 |
| **默认是关的** | 怕吵到人，所以默认关闭。右键悬浮球 → 「开启自动翻译」，或在设置面板最上面的开关里打开。**开关状态会记住**，下次启动保持上次的样子 |
| **首次使用引导** | 第一次跑 v2.5 会有一段两步引导：小手指着悬浮球提示「新增自动聊天翻译功能」，右键点开后小手移到「自动翻译」上高亮，其余地方用半透明灰色蒙布遮住。**只出现一次** |
| **两套气泡互不干扰** | 悬停气泡和自动气泡是两套独立实例。已经有自动气泡的消息，鼠标移上去不会再弹悬停气泡（否则两层字叠在一起看不清） |
| **翻译请求排队限流** | 频道一活跃可能一分钟十几条新消息，请求会串行排队、每条之间留 150ms 间隔，不会瞬间打爆接口 |
| **只翻屏幕里看得见的** | 屏幕外翻好了也没人看，还会把气泡挤到窗口边缘。所以只翻当前屏幕里看得见的；滚动停下后再补翻刚滚进来的 |
| **气泡对齐到文字** | 气泡水平居中到**文字本身**，不是整行容器 —— 短句子的气泡不会飘到右边的空白处 |
| **滚出屏幕立刻消失** | 消息滚出屏幕，气泡**立刻撤掉、不做淡出**（淡出会让气泡一边消失一边被夹到窗口顶上，看着像堆了一摞） |
| **气泡 15 秒自动消失** | 每条气泡最多停留 15 秒就淡出，看过的不会一直杵在句子上方 |
| **引用只翻正文** | 带"回复引用"的消息只翻正文。Discord 把引用预览排在正文之前、还复用了同一个 `message-content-` id 前缀，早期版本会把引用也翻一遍，同一句话出两个气泡 |

> v2.4 及更早的改动见 `方案文档.md`。

## 一、使用前提

| 要求 | 说明 |
|------|------|
| 系统 | Windows 10 / 11 |
| Discord | 桌面版（网页版不适用） |
| 网络 | 需要能正常登录 Discord（国内需自备代理） |
| API Key | 每人需要**自己申请**一个（见下） |

## 二、快速开始

**1. 申请自己的 DeepSeek API Key**

打开 <https://platform.deepseek.com/> 注册 → 创建 API Key（`sk-` 开头）。
新账号有免费额度，日常浏览聊天记录一个月通常只要几毛钱。

> ⚠️ 不要几个人共用一个 Key：额度会被一个人用光，而且所有人都能看到这个 Key。

**2. 双击 `launcher.exe`**

程序会自动完成：检查是否已有带调试接口的 Discord（有就**直接复用**）→ 没有则结束当前 Discord、带调试接口重新启动 → 等待主界面 → 注入翻译功能。

> 启动前请保存好 Discord 里正在输入的内容，因为**需要重启时它会先关闭 Discord**。
> 如果 Discord 已经是通过 `launcher.exe` 启动的（带调试接口），这次会直接复用，不会关掉它。

**3. 首次配置**

右下角出现半透明「译」字圆球后，右键它 → **设置** → 粘贴你的 API Key → 点「测试」确认可用 → 保存。

设置面板里还能改这些（都在同一个面板）：

| 项 | 作用 |
|---|---|
| **自动聊天翻译** | 面板最上面的开关（带 NEW 标记）。开了之后聊天区的新消息会自动出译文气泡，最多保留 6 条。**默认关**，状态会记住 |
| 界面语言 | 菜单和面板的语言：简体中文 / English |
| 目标语言 | 想翻译成哪种语言（13 种可选） |
| 气泡颜色 | 12 个预设色 + 自定义取色器；文字颜色会自动配（浅底深字、深底浅字） |
| 气泡透明度 | 10% ~ 100% |
| 触发延迟 | 鼠标停多久才翻译，100 ~ 1000ms |

面板底部有**实时预览**，改颜色和透明度能立刻看到效果。

**4. 开始使用**

- **悬停翻译**：鼠标悬停在消息上 → 上方弹出译文气泡；鼠标移开 → 气泡消失
- **自动聊天翻译**（要先打开开关）：聊天区来新消息就自动出译文气泡，最多同时保留 6 条

## 二·二、自动聊天翻译怎么用

打开开关的两种方式（效果一样，开关状态都存在 `dt_config.json` 里）：

1. 右键悬浮球 → **开启自动翻译**
2. 右键悬浮球 → 设置 → 最上面的「自动聊天翻译」开关

打开之后：

| 行为 | 说明 |
|---|---|
| 触发范围 | 聊天区**所有**新消息（自己发的、别人发的都翻） |
| **只翻看得见的** | 只翻**当前屏幕里看得见**的消息。屏幕外的翻了也没人看，气泡还会被挤到窗口边缘 |
| 气泡位置 | 贴在消息**正上方**，并且**水平居中对齐到文字本身**（不是整行容器）—— 短句子也不会飘到右边的空白处 |
| 条数上限 | **6 条**。第 7 条进来时，最旧的那条**渐变淡出** |
| **停留时长** | 每条气泡**最多 15 秒**，过期自动淡出（`dt_config.json` 里的 `autoTtl` 可改，单位毫秒） |
| 刚进频道 | 等 Discord 滚到底部（约 0.5 秒）后，把**屏幕上**已有的最新 6 条补翻一遍 |
| 滚动 | 消息滚出屏幕 → 气泡**立刻消失**（不做淡出，免得挤在窗口顶上）；滚进来新消息 → 停下后补翻 |
| **引用 / 回复** | 带"回复引用"的消息**只翻正文**，引用预览（那段被引用的原文）不翻 —— 否则同一句话会被翻两遍 |
| **转发消息** | 照常翻（转发卡片里的正文是消息主体，不是引用预览） |
| 向上翻历史 | 只会翻译「新来的」消息。往上滚动加载出来的旧消息不会翻，免得一口气发几十个请求 |
| 悬停冲突 | 已经有自动气泡的消息，鼠标移上去**不会**再弹悬停气泡 |
| 切频道 | 旧气泡全部清掉，重新翻新频道的最新 6 条 |
| 翻译失败 | 只在控制台留痕 + 弹一次提示，不会每条消息都弹一次 |

> **为什么不做「只翻别人发的」**：要判断一条消息是不是自己发的，得去读 Discord 内部的数据结构，那东西 Discord 一改版就会失效，而且会拖慢每条消息的判断。所以现在**谁发的都翻**。

## 二·五、多语言是怎么工作的

设置里的**目标语言**决定翻译方向：

- 鼠标悬停的文本**只要不是目标语言**，就翻译成目标语言
- 悬停的文本**已经是目标语言**，就**不翻译**，也不发请求（所以更快、更省）

举例：

| 目标语言 | 悬停英文 | 悬停中文 | 悬停俄文 |
|---|---|---|---|
| 简体中文 | 翻成中文 | 不翻译 | 翻成中文 |
| Русский | 翻成俄语 | 翻成俄语 | 不翻译 |
| English | 不翻译 | 翻成英语 | 翻成英语 |

判断"是不是目标语言"在本地完成，用两套办法：
1. **字符集判断** —— 中文/日文/韩文/俄文/泰文/阿拉伯文各有专属字符，识别几乎不会错
2. **虚词打分** —— 剩下的拉丁字母文本（英/西/法/德/葡/意/越）按常见虚词投票

识别不出来时（太短、纯数字、纯表情）会交给大模型，模型发现原文已是目标语言会原样返回，页面比对后就不显示气泡 —— 所以**任何情况下都不会弹出"和原文一模一样"的气泡**。

## 四、重要说明

**launcher.exe 必须保持运行。** 它不只是启动器，同时是翻译请求的转发器——关掉它翻译就会停止。
启动后它的窗口会自动隐藏，不用管它。要彻底退出：右键悬浮球 → 退出翻译助手。

**每次都要用 launcher.exe 启动 Discord。** 直接用 Discord 自带的快捷方式启动不会加载翻译功能（因为没有开启调试接口）。

**必须用 launcher.exe 重新启动的原因**：Discord 已经在运行时，它不会接受新的启动参数，所以程序会先关掉它再用新参数拉起。

## 五、常见问题

**Q: 右下角没有悬浮球？**

按顺序排查：

1. 确认是用 `launcher.exe` 启动的（不是 Discord 自己的快捷方式）
2. 确认代理软件开着（Discord 能正常登录）
3. 看同目录下的 `dt_bridge.log`，它按 `[0/4]` ～ `[4/4]` 打点，直接指出卡在哪一步
4. **关掉防火墙和杀毒软件再试一次** —— 这是最常见的真实原因，详见下一问

**Q: 把杀毒软件关掉才有悬浮球，怎么办？**

说明安全软件拦住了 Discord 的调试接口（`127.0.0.1:9333`）—— 而注入必须靠它。
典型表现是日志停在 `[3/4] 等待 Discord 主界面`，Discord 本身用起来完全正常。

**⚠️ 不要长期关着杀毒软件**，正确做法是加白名单：

1. **安全软件信任区**里同时加入 `Discord.exe` 和 `launcher.exe`
   - 360：设置 → 信任区 → 添加文件 / 目录
   - 火绒：防护中心 → 信任区
   - Windows Defender：病毒和威胁防护 → 排除项 → 添加排除项
2. **Windows 防火墙**：允许 `Discord.exe` 通过（勾「专用网络」即可，不用勾公用网络）
3. 加完白名单后重新双击 `launcher.exe`

公司电脑如果有统一的安全管控策略（必须开着某款安全软件且不能改配置），
找 IT 同事把这两个程序加进放行名单即可。

**Q: 双击 exe 后 Windows 提示"已保护你的电脑"/ 杀毒软件报警？**

这是 PyInstaller 打包程序的常见误报（因为很多恶意软件也用同样的打包方式），不是真的病毒。可以：
1. 点「更多信息」→「仍要运行」
2. 如果被杀毒软件拦截，把 `launcher.exe` 加入白名单

如果公司电脑安全策略很严，建议先让 IT 同事过一眼，或者直接用源码运行 `launcher.py`（需要 Python + `websocket-client`）。

**Q: 提示"翻译服务未连接"？**

`launcher.exe` 已经退出了，重新双击它即可。悬浮球右键菜单里能看到「翻译服务已连接 / 未连接」。

**Q: 提示"DeepSeek 账户余额不足"？**

去 <https://platform.deepseek.com/> 充值。

**Q: 有些消息悬停没反应？**

先确认这几类，它们本来就不翻译：
- **已经是目标语言的内容**（比如目标语言是中文，悬停中文消息就不翻）
- 纯表情、纯链接、纯图片/视频消息
- 用户名、时间戳等界面元素

机器人发的**卡片消息（Embed）是支持的**。如果某条卡片还是不翻译，把截图发出来，多半是 Discord 又换了新的 DOM 结构。

**Q: 自动聊天翻译怎么开？为什么默认是关的？**

默认关是**故意的** —— 它会一直在后台翻聊天记录，比悬停翻译更耗额度、也更"吵"，所以让用户自己决定要不要开。

开的方式：右键悬浮球 → **开启自动翻译**，或者右键 → 设置 → 最上面那个带 `NEW` 的开关。
开完之后状态会存进 `dt_config.json`，下次启动保持上次的样子。

> 第一次跑 v2.5 时会自动弹一段两步引导（小手指着悬浮球 → 指着「自动翻译」），跟着点一下就会开了。这段引导**只出现一次**。

**Q: 自动翻译的气泡最多几个？怎么让它少一点？**

**固定 6 条**，这是写死的上限 —— 多了会糊满整个聊天区。第 7 条新消息进来时，最旧的那条会**渐变淡出**。

而且只翻**当前屏幕里看得见**的消息，屏幕外的不翻 —— 翻了你也看不到，还会把气泡挤到窗口边缘。

如果 6 条还是嫌多，直接右键悬浮球 → **关闭自动翻译**即可（悬停翻译不受影响，照常可用）。

**Q: 气泡会一直停在消息上面吗？**

不会。每条气泡**最多停留 15 秒**，到时间就自动淡出 —— 看过的不会一直杵在那儿挡着。

想改这个时长，用记事本打开 `dt_config.json`，把 `"autoTtl": "15000"` 改成你要的毫秒数（比如 `"30000"` 就是 30 秒），重启程序生效。

**Q: 滚动聊天时气泡会跟着跑吗？**

会跟着消息一起滚。但消息**滚出屏幕**的那一刻，气泡**立刻消失**（不做淡出动画）—— 不然气泡会一边慢慢消失一边被夹到窗口顶上，看着像一堆气泡堆在顶部。

反过来，滚到底之后，刚滚进屏幕的新消息会**自动补翻**，不用手动操作。

**Q: 有人回复别人时，被引用的那句话会翻吗？**

**不翻，只翻回复的正文。**

原因：Discord 把"回复引用"渲染在正文**之前**，而且引用预览的文本元素**复用了被引用消息的 `message-content-<id>`**。早期版本按 id 前缀取第一个匹配，取到的就是引用预览 —— 结果同一句话被翻两遍（原消息一次、引用一次），看着像坏了。现在改成"按本条消息自己的 id 精确取正文"，引用预览就不会被翻。

那如果想看被引用那句话的译文呢？**鼠标悬停在引用上**就行 —— 悬停翻译是"指哪翻哪"，不受这个限制。

**Q: 转发消息（Forward）会翻吗？**

**会，照常翻。** 转发卡片里的正文就是消息主体（不是"引用预览"），所以没有被上面那条规则排除掉。

**Q: 我自己发的消息也被翻译了？**

是的，**谁发的都翻**。

原本设计里想只翻别人发的，但判断"这条是不是自己发的"要读 Discord 内部的数据结构，那东西 Discord 一改版就失效，而且每条消息都要多判断一次、拖慢速度。所以最后决定不做这个区分。

**Q: 往上翻聊天记录，旧消息怎么不翻译？**

**故意的**。自动翻译只翻「新来的」消息 —— 靠消息 ID（Discord 的消息 ID 是随时间递增的雪花 ID）判断：比见过的最大 ID 还大才是新消息。

否则往上滚一次就可能加载出几十条旧消息，全翻一遍既慢又费额度。

**Q: 第一次打开时那个小手指的提示，怎么关掉？**

点提示卡上的「**知道了**」，或者跟着走一步（右键悬浮球 → 开启自动翻译）就会消失。

它**只在第一次运行 v2.5 时出现一次**，之后不会再弹。如果想再看一遍，把 `dt_config.json` 里的 `"guideDone"` 改成 `""` 再重启即可。

**Q: 悬停到一条已经有自动气泡的消息上，怎么不出悬停气泡了？**

这是**故意的**：两套气泡贴在同一个位置，一起出来会叠成两层字看不清。所以已经有自动气泡的消息，悬停时就不再弹悬停气泡了。

**Q: 重启了 launcher.exe，但翻译一直提示"服务响应超时"？**

正常情况下程序启动时会自动清理上一次的残留通道，不用管。如果日志里出现「通道自检未通过」，在 Discord 里按一次 `Ctrl+R` 刷新页面即可。

**Q: 点「保存设置」后提示「设置已生效，但没存进文件，重启会丢」？**

说明这次设置**在本次会话里已经生效**，但没能写进 `dt_config.json`。常见原因：

1. 程序被放在了 `C:\Program Files` 这类需要管理员权限的目录 → 把整个文件夹移到「文档」「桌面」或 `D:\` 下再试
2. `dt_config.json` 被设成了「只读」→ 右键文件 → 属性 → 取消「只读」
3. 杀毒软件拦截了文件写入 → 把整个程序目录加入信任区

改完重试即可，设置面板会**保持打开**方便你再点一次保存。

**Q: 启动时提示端口 9333 被占用 / 想换个端口？**

用记事本打开 `dt_config.json`，加一行：

```json
"debugPort": "9334"
```

保存后重新双击 `launcher.exe`。也可以用环境变量临时指定（比如 `set DT_PORT=9334` 后再启动），环境变量优先级更高。

**Q: 我用的是 Discord 里内嵌的小游戏 / 活动，那里会不会也冒出悬浮球？**

不会。脚本只在外层 Discord 窗口创建界面，内嵌的网页内容（活动、小游戏）里不会出现。

**Q: 会不会影响 Discord 账号 / 会被封号吗？**

程序只在运行时往页面里注入界面元素，不改 Discord 文件、不碰账号登录信息、不自动化任何账号操作，风险很低。但它确实是通过调试接口注入的，严格来说属于非官方增强，是否使用请自行判断。

## 七、技术原理（给好奇的人）

Discord 桌面版是 Electron 应用。这个工具做了三件事：

1. **用调试端口启动 Discord**，通过 Chrome DevTools Protocol 注入脚本，往页面里加悬浮球和气泡
   （试过 Chrome 扩展方案，但 Electron 不执行扩展的 content script，此路不通）

2. **直接读页面的真实文字**，而不是截图 + OCR 识别，所以准确率和速度都远好于 OCR

3. **翻译请求由外部程序（launcher.exe）代发**
   Discord 页面有 CSP `connect-src` 限制，页面里直接请求外部 API 会报 `Failed to fetch`。
   所以页面脚本通过 CDP 的 `Runtime.addBinding` 注册的原生函数，把翻译请求"呼叫"给 launcher.exe，
   由它用 Python 发 HTTPS 请求，再把结果回传页面渲染。

更完整的踩坑记录见 `方案文档.md`。
