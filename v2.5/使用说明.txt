=========================================
   Discord 实时翻译助手 v2.5
=========================================

两种用法：
  · 鼠标悬停消息 -> 弹出译文气泡（一直都有）
  · 自动聊天翻译 -> 新消息自动出译文（v2.5 新增，默认关）


【本版（v2.5）改了什么】

* 自动聊天翻译（新功能）
  聊天区来了新消息就自动出译文气泡，最多同时保留 6 条，
  第 7 条进来时最旧的那条"渐变淡出"。
  只翻当前屏幕里看得见的；每条气泡最多停留 15 秒就自动淡出。
  气泡贴在消息正上方，跟着聊天记录一起滚，不会错位。
* 默认是关的
  怕吵到人，所以默认关闭。
  右键悬浮球 -> "开启自动翻译" 就能打开。
  开关状态会记住，下次启动保持上次的样子。
* 首次使用引导
  第一次跑 v2.5 会有两步引导：小手指着悬浮球提示
  "新增自动聊天翻译功能"，右键点开后小手移到"自动翻译"
  上高亮，其余地方用半透明灰色蒙布遮住。只出现一次。
* 两套气泡互不干扰
  已经有自动气泡的消息，鼠标移上去不会再弹悬停气泡
  （否则两层字叠在一起看不清）。
* 翻译请求排队限流
  频道一活跃可能一分钟十几条新消息，请求会串行排队、
  每条之间留 150ms 间隔，不会瞬间打爆接口。
* 只翻屏幕里看得见的
  只翻当前屏幕里看得见的消息，屏幕外的不翻 —— 翻了也没人
  看，还会把气泡挤到窗口边缘。滚动停下后会补翻刚滚进来的。
* 气泡对齐到文字
  气泡水平居中对齐到"文字本身"，不是整行容器 ——
  短句子的气泡不会飘到右边的空白处，一眼能看出翻的是哪句。
* 滚出屏幕立刻消失
  消息滚出屏幕，气泡立刻撤掉、不做淡出动画
  （淡出会让气泡一边消失一边被夹到窗口顶上，像堆了一摞）。
* 气泡 15 秒自动消失
  每条气泡最多停留 15 秒就自动淡出，看过的不会一直杵着。
  想改时长：记事本打开 dt_config.json，把 "autoTtl": "15000"
  改成你要的毫秒数（比如 "30000" = 30 秒），重启生效。
* 引用只翻正文
  有人"回复"别人时，只翻回复的正文，被引用的那句话不翻 ——
  否则同一句话会被翻两遍（原消息一次、引用一次）。
  想看被引用那句话的译文：鼠标悬停在引用上即可。

（v2.4 及更早的改动见 方案文档.md）


【快速开始】

1. 保持代理软件（v2rayN 等）开启且正常工作

2. 双击 launcher.exe

3. 程序会自动：
   - 检查是否已有带调试接口的 Discord（有就直接复用）
   - 没有则结束当前 Discord，重新启动（带调试接口）
   - 等待主界面加载
   - 注入翻译功能并建立翻译通道

4. 看到右下角出现半透明"译"字圆球 = 成功
   （启动窗口会自动隐藏，程序在后台继续运行）

5. 首次使用：右键悬浮球 -> 设置 -> 填入 DeepSeek Key -> 点"测试"-> 保存
   API Key 免费获取：https://platform.deepseek.com/ 注册后创建

   同一个设置面板里还能改：
     自动聊天翻译 最上面的开关（带 NEW 标记），默认关
                  开了之后聊天区新消息自动出译文，最多保留 6 条
     界面语言   简体中文 / English（外国同事用这个）
     目标语言   想翻译成哪种语言（13 种）
     气泡颜色   12 个预设色 + 自定义取色器
     气泡透明度 10% ~ 100%
     触发延迟   100 ~ 1000ms
   面板底部有实时预览，改颜色和透明度立刻能看到效果

6. 鼠标悬停在消息上 -> 译文气泡显示在原文正上方
   鼠标离开 -> 气泡立刻消失

7. 想用"自动聊天翻译"：右键悬浮球 -> 开启自动翻译
   （或者在设置面板最上面打开那个开关）


【自动聊天翻译怎么用】

打开开关的两种方式（效果一样，状态都存在 dt_config.json）：
  1) 右键悬浮球 -> 开启自动翻译
  2) 右键悬浮球 -> 设置 -> 最上面的"自动聊天翻译"开关

打开之后：
  - 触发范围   聊天区所有新消息（自己发的、别人发的都翻）
  - 只翻屏幕内 只翻当前屏幕里看得见的消息。屏幕外的不翻，
               滚进来之后再补翻
  - 气泡位置   贴在消息正上方，水平居中对齐到"文字本身"
               （不是整行），跟着聊天记录一起滚
  - 条数上限   6 条。第 7 条进来时，最旧的那条渐变淡出
  - 停留时长   每条气泡最多 15 秒，过期自动淡出
               （dt_config.json 里的 autoTtl 可改，单位毫秒）
  - 刚进频道   等 Discord 滚到底（约 0.5 秒）后，把屏幕上
               已有的最新 6 条补翻一遍
  - 滚动       消息滚出屏幕 -> 气泡立刻消失（不做淡出）；
               滚进来新消息 -> 停下后补翻
  - 引用/回复  带"回复引用"的消息只翻正文，引用预览不翻
               （想看被引用那句：鼠标悬停在引用上即可）
  - 转发消息   照常翻（转发卡片里的正文是消息主体，不算引用）
  - 向上翻历史 只翻"新来的"消息。往上滚动加载出来的旧消息
               不会翻，免得一口气发几十个请求
  - 悬停冲突   已经有自动气泡的消息，鼠标移上去不会再弹
               悬停气泡
  - 切频道     旧气泡全部清掉，重新翻新频道的最新 6 条
  - 翻译失败   只在控制台留痕 + 弹一次提示，不会刷屏

为什么不做"只翻别人发的"：
  要判断一条消息是不是自己发的，得去读 Discord 内部的
  数据结构，那东西 Discord 一改版就会失效，而且会拖慢
  每条消息的判断。所以现在谁发的都翻。


【重要说明】

* launcher.exe 启动后必须保持运行（窗口会自动隐藏，不用管它）
  它同时是"翻译请求的转发器"，关掉它翻译就会停止
  要彻底退出：右键悬浮球 -> 退出翻译助手

* 每次都要用 launcher.exe 启动 Discord
  直接用 Discord 自带快捷方式启动不会加载翻译功能

* 需要重启 Discord 时，launcher.exe 会先把它关掉再重启
  启动前请保存好正在输入的内容
  （如果 Discord 已经是通过 launcher.exe 启动的，
    这次会直接复用，不会关掉它）

* 必须开着代理软件（Discord 本身在国内需要代理才能使用）

* 需要把 Discord 和 launcher.exe 加入安全软件白名单
  否则安全软件会拦住调试接口，导致"Discord 正常但没有悬浮球"
  详见下面【常见问题】第 2 条


【悬浮球操作】

- 左键单击：开启/关闭翻译（绿边=开，红边=关）
- 右键单击：功能菜单（开启/关闭自动翻译 / 设置 / 清缓存 / 收起 / 退出）
- 拖拽：移动到任意位置（自动记忆）
  位置按"距右下角的距离"记录，窗口放大/还原都不会跑丢
- 双击：收起为小点（再双击展开）
- 10秒不操作：自动变暗到 15%（不干扰观看）
- 鼠标放上去：恢复正常显示


【翻译功能】

- 鼠标悬停消息 -> 自动翻译（防抖延迟默认 300ms，可调）
- 翻译结果以半透明气泡显示在消息正上方
- 气泡不遮挡内容（鼠标可穿透），离开立刻消失
- 相同句子自动缓存，不重复请求 API、不重复扣费
- 气泡颜色、透明度可调（设置面板，带实时预览）

支持的翻译对象：
- 普通文字消息
- 机器人卡片消息（Embed / 新版 Components V2 卡片，如抽奖、投票、公告）
  悬停在卡片里某一段文字 -> 只翻译那一段
  悬停在卡片留白处 -> 翻译整张卡片

翻译方向（由"目标语言"决定）：
- 悬停的文本只要不是目标语言，就翻译成目标语言
- 悬停的文本已经是目标语言，就不翻译、也不发请求（更快更省钱）

  目标语言=简体中文：英文消息->翻成中文   中文消息->不翻   俄文消息->翻成中文
  目标语言=Русский  ：英文消息->翻成俄语   中文消息->翻成俄语  俄文消息->不翻
  目标语言=English  ：英文消息->不翻       中文消息->翻成英语  俄文消息->翻成英语

  可选：简体中文 / English / 日本語 / 한국어 / Русский / Español / Français /
        Deutsch / Português / Italiano / Tiếng Việt / ไทย / العربية

不翻译的内容（设计如此）：
- 已经是目标语言的内容
- 纯表情、纯链接、纯图片/视频消息
- 用户名、时间戳等界面元素


【配置文件】

dt_config.json（和 launcher.exe 同目录）保存了所有设置：

  apiKey      DeepSeek API Key
  enabled     1=翻译开启 0=翻译关闭
  uiLang      界面语言：zh=简体中文 en=English
  targetLang  目标语言：zh / en / ja / ko / ru / es / fr / de / pt / it / vi / th / ar
  bubbleBg    气泡背景色（#RRGGBB）
  opacity     气泡透明度 0.1~1
  debounce    触发延迟（毫秒）
  model       使用的模型（默认 deepseek-chat）
  ballRight   悬浮球距右边的距离（像素）
  ballBottom  悬浮球距下边的距离（像素）
              （v2.3 及更早存的是 ballX/ballY 绝对坐标，
                升级后会自动换算一次，之后就用上面这两个）
  debugPort   调试端口（可选，默认 9333；被占用或想避开时改）
  autoTranslate 自动聊天翻译开关：1=开 0=关（v2.5，默认 0）
  guideDone   首次使用引导是否已看过（v2.5，看过就是 "1"）
              想再看一遍引导，把它改成空字符串 "" 再重启即可

可以直接用记事本编辑（改完重启程序生效），
也可以在悬浮球右键菜单里改（即时生效）。

注意：dt_config.json 里保存了你的 API Key，
      分享给他人前请把 apiKey 字段清空。


【常见问题】

Q: 右下角没有悬浮球？
A: 按顺序排查：
   1) 确认是用 launcher.exe 启动的（不是 Discord 自己的快捷方式）
   2) 确认代理软件已开启（Discord 能正常登录）
   3) 看同目录下 dt_bridge.log 里的日志
      它按 [0/4] ~ [4/4] 打点，直接指出卡在哪一步
   4) 关掉防火墙和杀毒软件再试一次
      这是最常见的真实原因，详见下一问

Q: 把杀毒软件关掉才有悬浮球，怎么办？
A: 说明安全软件拦住了 Discord 的调试接口（127.0.0.1:9333），
   而注入必须靠它。
   典型表现：日志停在 [3/4] 等待 Discord 主界面，
   但 Discord 本身用起来完全正常。

   ！！不要长期关着杀毒软件 ！！正确做法是加白名单：

   1) 安全软件"信任区"里同时加入 Discord.exe 和 launcher.exe
        360           设置 -> 信任区 -> 添加文件/目录
        火绒          防护中心 -> 信任区
        Windows Defender  病毒和威胁防护 -> 排除项 -> 添加排除项
   2) Windows 防火墙：允许 Discord.exe 通过
        （勾"专用网络"即可，不用勾公用网络）
   3) 加完白名单后重新双击 launcher.exe

   公司电脑如果有统一的安全管控策略（必须开着某款安全软件
   且不能改配置），找 IT 同事把这两个程序加进放行名单即可。

Q: 双击 exe 后 Windows 提示"已保护你的电脑" / 杀毒软件报警？
A: 这是 PyInstaller 打包程序的常见误报（很多恶意软件也用同样的
   打包方式），不是真的病毒。可以：
   1) 点"更多信息" -> "仍要运行"
   2) 如果被杀毒软件拦截，把 launcher.exe 加入白名单
   公司电脑安全策略很严的话，先让 IT 同事过一眼，
   或者直接用源码运行 launcher.py（需 Python + websocket-client）

Q: 翻译没反应 / 显示"翻译服务未连接"？
A: launcher.exe 已退出。重新双击 launcher.exe 即可
   （悬浮球右键菜单会显示"翻译服务已连接/未连接"）

Q: 重启 launcher.exe 后一直提示"翻译服务响应超时"？
A: 程序启动时会自动清理上一次的残留通道，一般不会出现。
   万一出现，日志里会写"通道自检未通过"，
   在 Discord 里按一次 Ctrl+R 刷新页面即可。

Q: 点"保存设置"后提示"设置已生效，但没存进文件，重启会丢"？
A: 说明这次设置在本次会话里已经生效，但没能写进 dt_config.json。
   常见原因：
   1) 程序放在了 C:\Program Files 这类需要管理员权限的目录
      把整个文件夹移到"文档"/"桌面"/D 盘再试
   2) dt_config.json 被设成了"只读"
      右键文件 -> 属性 -> 取消"只读"
   3) 杀毒软件拦截了文件写入
      把整个程序目录加入信任区
   改完重试即可，设置面板会保持打开方便你再点一次保存。

Q: 启动时提示端口 9333 被占用 / 想换个端口？
A: 用记事本打开 dt_config.json，加一行：
       "debugPort": "9334"
   保存后重新双击 launcher.exe。
   也可以用环境变量临时指定（set DT_PORT=9334 后再启动），
   环境变量优先级更高。

Q: 悬停消息没有任何反应？
A: 先确认不是这几种情况：
   - 内容已经是"目标语言"了（比如目标语言是中文，悬停中文消息本来就不翻）
   - 纯表情 / 纯链接 / 纯图片视频
   如果是机器人卡片还不翻，把截图发出来

Q: 自动聊天翻译怎么开？为什么默认是关的？
A: 默认关是故意的 —— 它会一直在后台翻聊天记录，
   比悬停翻译更耗额度、也更"吵"，所以让用户自己决定。
   开的方式：右键悬浮球 -> 开启自动翻译，
   或者右键 -> 设置 -> 最上面那个带 NEW 的开关。
   开完之后状态会存进 dt_config.json，下次启动保持原样。
   第一次跑 v2.5 时会自动弹一段两步引导（小手指着悬浮球
   -> 指着"自动翻译"），跟着点一下就会开了。
   这段引导只出现一次。

Q: 自动翻译的气泡最多几个？怎么让它少一点？
A: 固定 6 条，这是写死的上限 —— 多了会糊满整个聊天区。
   第 7 条新消息进来时，最旧的那条会渐变淡出。
   如果 6 条还是嫌多，直接右键悬浮球 -> 关闭自动翻译即可
   （悬停翻译不受影响，照常可用）。

Q: 我自己发的消息也被翻译了？
A: 是的，谁发的都翻。原本设计里想只翻别人发的，但判断
   "这条是不是自己发的"要读 Discord 内部的数据结构，
   那东西 Discord 一改版就失效，而且每条消息都要多判断
   一次、拖慢速度。所以最后决定不做这个区分。

Q: 往上翻聊天记录，旧消息怎么不翻译？
A: 故意的。自动翻译只翻"新来的"消息 —— 靠消息 ID 判断
   （Discord 的消息 ID 是随时间递增的雪花 ID），
   比见过的最大 ID 还大才是新消息。
   否则往上滚一次就可能加载出几十条旧消息，
   全翻一遍既慢又费额度。

Q: 第一次打开时那个小手指的提示，怎么关掉？
A: 点提示卡上的"知道了"，或者跟着走一步
   （右键悬浮球 -> 开启自动翻译）就会消失。
   它只在第一次运行 v2.5 时出现一次，之后不会再弹。
   想再看一遍，把 dt_config.json 里的 "guideDone"
   改成空字符串 "" 再重启即可。

Q: 悬停到一条已经有自动气泡的消息上，怎么不出悬停气泡了？
A: 故意的：两套气泡贴在同一个位置，一起出来会叠成两层字
   看不清。所以已经有自动气泡的消息，悬停时就不再弹。

Q: 在 Discord 里玩内嵌的小游戏/活动，会不会也冒出悬浮球？
A: 不会。脚本只在外层 Discord 窗口创建界面，内嵌内容里不会出现。

Q: 提示"DeepSeek 账户余额不足"？
A: 去 https://platform.deepseek.com/ 充值即可，新账号有免费额度

Q: 提示"API Key 无效"？
A: 检查 Key 是否复制完整（以 sk- 开头），或在设置里点"测试"验证

Q: 为什么必须用 launcher.exe？
A: 翻译功能通过调试接口注入到 Discord，需要特定启动参数，
   直接用 Discord 快捷方式启动无法注入

Q: 为什么启动时 Discord 被关闭了？
A: 已运行的 Discord 没有开启调试接口，必须先关闭再用新参数启动。
   如果它已经是通过 launcher.exe 启动的（带调试接口），
   v2.4 会直接复用，不会再关掉它。

Q: 会不会影响 Discord 本身 / 会被封号吗？
A: 不会修改 Discord 任何文件，只在运行时注入界面元素，
   也不读取你的账号密码。属于本地辅助工具，风险极低

Q: API 收费吗？
A: DeepSeek 价格很低（约 1 元 / 百万字），相同句子有缓存不重复扣费
   日常浏览聊天记录，一个月通常几毛钱

【技术原理】

Discord 桌面版基于 Electron。实测发现：
  (1) Electron 不完整支持 Chrome 扩展，--load-extension 的
      content script 不会执行 —— 所以放弃了扩展方案
  (2) Discord 页面设置了 CSP: connect-src，页面里 fetch 外部 API
      会直接报 "Failed to fetch" —— 所以放弃了页面直连

最终方案：CDP 注入 + 原生桥接

  launcher.exe
      | 带 --remote-debugging-port 启动
  Discord（Electron）
      | CDP 连接，注入 inject.js（悬浮球 + 气泡 + 悬停翻译 + 自动聊天翻译）
      |
  鼠标悬停 / 聊天区来新消息 -> 读取 DOM 真实文字（不是 OCR，100% 准确）
      |
  页面 JS 调用原生函数 __dtNative（CDP Runtime.addBinding）
      |
  launcher.exe（Python）代为请求 DeepSeek API  <- 绕开 CSP
      |
  结果回传页面 -> 半透明气泡显示在原文上方

优点：
  · 不依赖扩展机制，不受 Electron 限制
  · 直接读 DOM 文字，100% 准确、零延迟
  · 网络请求在 Python 侧发起，彻底绕开页面 CSP
  · 配置存本地文件，重启不丢失
